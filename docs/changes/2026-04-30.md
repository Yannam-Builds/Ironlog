## GEMINI REVIEW FINDINGS — 2026-04-30

### Critical Bugs

1. **History ID mismatch — data loss on delete/edit**
   - `ActiveWorkoutScreen.js` generates `id = Date.now().toString()` for the session object.
   - `workoutRepository.createCompletedWorkout` creates a WatermelonDB row with a UUID.
   - The UUID is never threaded back into AppContext's `history` array.
   - Result: `deleteHistoryEntry("timestamp")` silently fails on WM side; entry reappears on next boot.
   - Fix: return `workoutPrep` from `workoutRepository.js:330`, patch `entry.id` in `AppContext.addHistory`.

2. **Backup creates empty backups — all data lost on restore**
   - `getManagedStorageMap()` reads AsyncStorage keys that are now empty (data is in WatermelonDB).
   - `BACKUP_MANAGED_KEYS` in `backupConstants.js:16-31` lists `ironlog_plans`, `ironlog_history`, etc. — orphaned.
   - Backups capture nothing; restore returns an empty app.
   - Fix: replace `getManagedStorageMap` with `exportDatabase()` from `importExportRepository`.

3. **Active session prefix mismatch — sessions lost on crash + restore**
   - `workoutSessionStore.js:7` uses prefix `active_workout_session:`.
   - `backupConstants.js:1` and `ActiveWorkoutScreen.js:95` use `@ironlog/activeWorkoutSession/`.
   - Backup scanner never finds active sessions. In-progress workouts are not backed up or restorable.
   - Fix: unify prefix across all three files.

4. **Dual `savePlans` — plan writes will overwrite each other**
   - `PlansScreen` uses `useWatermelonPlans().savePlans` → `planRepository.replaceAllPlans`.
   - AppContext has its own `savePlans` (`AppContext.js:504`) which does a separate delete-all + recreate from stale boot-time state.
   - Any screen using `AppContext.savePlans` will wipe PlansScreen's WatermelonDB writes.
   - Fix: remove `AppContext.savePlans`; all screens use `useWatermelonPlans`.

5. **SmokeTest model not registered in database.js**
   - `SmokeTest.js` model exists but is not in `modelClasses` array.
   - Any access to `db_smoke_tests` via the model API throws at runtime.

### Architecture Issues

- **Two live sources of truth:** `useWatermelonPlans/Home/Settings` hooks observe WatermelonDB live. AppContext holds a stale boot-time snapshot. Mutations via hooks don't update AppContext and vice versa.
- **Backup/notification config still 100% on AsyncStorage** — `backupService.js` imports AsyncStorage directly for all config keys. Not migrated.
- **No error boundaries** in AppNavigator or tab screens. Any screen crash = white screen, no recovery.

### Dead Code

- `src/db/models/SmokeTest.js` + `src/db/repositories/smokeRepository.js` — unregistered/unreachable
- `src/db/index.js` — re-export barrel; all imports use `../db/database` directly
- `src/domain/storage/trainingDatabase.js` + `trainingRepository.js` — likely unreachable from active import tree
- Legacy `BACKUP_MANAGED_KEYS` entries — orphaned AsyncStorage keys holding no data

### Priority Fix Order

1. History ID mismatch (`workoutRepository.js`, `AppContext.js`)
2. Backup export via WatermelonDB not AsyncStorage (`backupService.js`, `backupConstants.js`)
3. Active session prefix unification (`workoutSessionStore.js`, `backupConstants.js`, `ActiveWorkoutScreen.js`)
4. Remove dual `savePlans` — unify on `useWatermelonPlans` (`AppContext.js`, `PlanEditorScreen.js`, `ProgramPickerScreen.js`)
5. Register or delete `SmokeTest` model (`database.js`, `schema.js`)
6. Add `ErrorBoundary` component to screen tree (`AppNavigator.js`)
7. Migrate backup/notification config to WatermelonDB `app_settings` (`backupService.js`)
8. Make AppContext history reactive to WatermelonDB observable (`AppContext.js`)
9. Delete confirmed dead files (`trainingDatabase.js`, `trainingRepository.js`, `smokeRepository.js`, `SmokeTest.js`)
